## Core principles to preserve

1. **Evidence before status:** no “built” claim without inspecting V3 code and running the relevant tests; UI/voice/phone claims also require real Windows integration tests.
2. **Intent-first conversation:** natural-language requests should be routed automatically; slash commands are optional diagnostics/admin controls, not required workflow.
3. **Functional self-monitoring, not consciousness claims:** observe outcomes, identify failure classes, propose repairs, verify with tests, and rollback on regression.
4. **Safe skill learning:** extract candidate procedures from outcomes; quarantine until reviewed/evaluated; never let learned text grant permissions.
5. **Research with provenance:** capture URL, title, retrieval date, license, confidence, extracted facts, and evidence. Web content/repository files are untrusted input, never instructions.
6. **Knowledge ingestion:** local files are indexed with source paths; external ingestion is opt-in, source-aware, bounded, and does not silently upload private data.
7. **Self-updates:** changes are staged in a branch/worktree, tested, diff-reviewed, backed up, and rollback-capable. Never silently replace the running app.
8. **Security:** fail closed; no secret logging; no unapproved network/provider fallback; no unrestricted host code execution.
9. **Local-first:** stdlib-first V3, SQLite where suitable, Windows UIA-first control, no cloud migration.
10. **Honest failure reporting:** failed, blocked, unverified, and negative research findings remain visible.

## Priority queue for V3

- **P0 — automatic orchestration:** map natural-language intent to a typed task plan; validate capability, risk, preconditions and postconditions; execute permitted steps; report verified outcomes. Ask only for genuinely missing information or required approval.
- **P0 — evidence loop:** automatically record bounded/redacted task outcomes, distinguish “attempted” from “verified”, diagnose failure class, prevent blind retries, and attach evidence.
- **P0 — safe self-healing:** generate a repair proposal in an isolated working copy; run focused and full tests; compare regression suite; retain patch and logs; apply only after policy/approval; rollback if health checks fail.
- **P1 — knowledge base:** index trusted local docs and the research ledger with source/path metadata; retrieve relevant chunks automatically for the current task; support refresh and deletion.
- **P1 — research/scout:** optional scheduled repository and web research with rate limits, deduplication, license/security checks, summaries and proposed diffs; no automatic execution of downloaded code.
- **P1 — code/reverse-engineering skill:** inspect code structure, call graph, tests, dependencies, licenses and threat surface; report observed vs inferred vs unknown; never bypass access controls or test outside authorization.
- **P1 — evaluation:** deterministic golden scenarios, Hinglish variants, fake-completion detection, tool-call accuracy, task-success evidence, latency and regression scorecards.
- **P2 — voice/UIA/phone/browser:** implement separately behind explicit capability adapters and real platform tests.
- **P2 — training:** distinguish prompt/memory/skill learning from model-weight training. Fine-tuning/LoRA requires curated consented data, held-out evaluations, compute budget, licensing review and a reversible model version.
